# ИИ-сторож

## Запуск CPU API с проверкой вложений и авторства писем

Из корня проекта в PowerShell выполните команды ниже. Для запуска достаточно локальных весов. Сервис на localhost становится доступен после прогрева основного и резервного процессов.

~~~powershell
python -m pip install -r requirements.txt
$env:STOROZH_VARIANT='B'
$env:STOROZH_ATTACHMENT_INTENT='13'
python -m uvicorn app.main:app --host 127.0.0.1 --port 8013
~~~

В режиме B/13 параметр агента `review_correspondence: true` в `security_policy.yaml` включает обученный классификатор авторства v28. Черновик для проверки будущим подписантом проходит обычные проверки. При просьбе выступить от чужого имени сервис возвращает `confirm`, если полномочия неясны. Распознанное намерение ложно приписать другому человеку авторство относится к `fraud_social_engineering`. Решение о проверке полномочий исполняет вызывающая система. [Обучение и результаты сравнения через API](experiment/v28/REPORT.md)

Клиент отправляет запрос на `POST /v1/check`. Сервис проверяет текст, вложения и полномочия по `security_policy.yaml`. При тайм-ауте текущий запрос получает `block` и `check_error`. Прогретый резерв принимает следующий запрос, пока новая копия загружает веса. Порог публикации проверяется по внешней выборке через этот же HTTP-маршрут. [Результаты v27 и команды оценки](experiment/v27/REPORT.md)

Локальный CPU-шлюз проверяет инструкцию перед обращением к агенту. Клиент отправляет текст, роль, историю и вложения. Ответ содержит решение, причину, категорию, уровень риска и время проверки. Базовое исследование описано в [отчёте v15](experiment/v15/REPORT.md).

Для проверки v28 на 64 примерах из восьми областей установите `requirements-dev.txt` и выполните `python -m experiment.v28.evaluate repeat fresh`. Команда запускает отдельный локальный API. Для проверки на публичных 500 примерах поместите файл организаторов в `artifacts/astra_public/dev.jsonl`. Исходные тексты внешних коллекций для повторения проверки на 336 документах восстанавливает команда `python -m experiment.v27.fetch` с установленным `pyarrow`. Снимки результатов предыдущих экспериментов приведены ниже. Команды сборки старых версий относятся к их исследовательским каталогам и архивам.

## Запуск

Проверенная среда — Windows x64, Python 3.10.11. В PowerShell из корня проекта:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
~~~

Откройте [демо](http://127.0.0.1:8001/) или [Swagger](http://127.0.0.1:8001/docs). Для Linux команды запуска используют .venv/bin/python. На машине без сети установите зависимости из заранее подготовленного каталога wheel для её ОС и версии Python через pip install --no-index --find-links. Все веса конкурсного пути локальные. Для воспроизведения точного проверенного Windows-окружения используйте experiment/v15/environment.lock.

~~~powershell
$packet = @{ user_prompt='Кто согласует перезапуск?'; context=@{ target_agent='it_ops_agent'; user_role='developer'; history=@(); attachments=@() } }
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8001/v1/check' -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes(($packet | ConvertTo-Json -Depth 8)))
~~~

POST /v1/check только оценивает. allow разрешает клиенту продолжить, confirm требует подтверждения, block останавливает запрос. Каждая проверка использует только присланный контекст. Роль из ключа клиента ограничивает допустимую context.user_role. На конкурсном стенде доверенный вызывающий компонент передаёт роль, полученную при аутентификации. Передача и подтверждение в демо находятся в отдельных маршрутах /v1/demo. Заглушка выдаёт локальную квитанцию. Изменение пакета, версии политики, владельца или истечение часа аннулирует прежнее разрешение.

Версии A/B/C и отдельная проверка длины сравниваются в таблицах отчёта. На 870 отложенных пакетах B показал p95 53,2 мс, максимум наблюдаемой RSS среди публичного и тематических прогонов около 243 МиБ. На нейтральных вложениях 32 000 и 64 000 символов p95 B составил 885 мс и 1 651 мс. На тематическом тесте B заблокировал 50% опасных high/critical при требовании 85%.

Вход принимает до 32 000 символов на текст и до 96 000 на совокупность текстов, до 64 реплик и 16 вложений. При ошибке входа или внутренней проверки авторизованный вызов получает JSON с HTTP 200 и block. Поле check_error отличает техническую остановку от распознанной угрозы. Ошибки аутентификации имеют собственные HTTP-коды. В журнале конкурсной проверки хранятся метаданные решения и отпечаток пакета. Текст запроса, история, вложения и значения секретов в него не записываются.

## Политика и доступ

Рабочий файл — security_policy.yaml. Его исходная копия находится в experiment/v15/security_policy.reference.yaml. ASTRA_POLICY_PATH позволяет выбрать другой файл. Шлюз проверяет содержимое при обращении, кэширует результат разбора по байтам, использует последнюю валидную версию при ошибке редактирования. При холодном старте с повреждённым файлом проверка завершается блокировкой. Версия в ответе и журнале — SHA256 активного файла. Используйте один процесс Uvicorn для демо и редактирования политики.

В agents перечисляются целевые агенты. Каждый описывает tools, tool_specs, environments и roles. Поле aliases задаёт буквальные фразы, patterns дополнительные регулярные выражения, literal_patterns полное совпадение для одной операции. Тип инструмента принимает read, modify, execute или destroy. Окружения задаются glob-шаблонами, environment_aliases привязывает разговорные названия. critical_environments влияет на тяжесть отказа. Для неуказанного окружения проверяются возможные окружения и выбирается наиболее строгое решение. Правила роли задаются на инструмент либо на пары инструмент–окружение. Неизвестный агент или роль получает block.

Каждый forbidden_action содержит name, description и patterns. Секции always_block и context_dependent задают категории. Для совместимости со старой схемой встроен справочник app/legacy_policy_defaults.yaml. В новом домене задайте собственные имена и явные описания. Четыре готовые независимые политики находятся в experiment/v15/sealed/schema-*.yaml. Пример проверки новой политики без перезаписи рабочей:

~~~powershell
$env:ASTRA_POLICY_PATH=(Resolve-Path 'experiment/v15/sealed/schema-1.yaml')
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8003
~~~

Для редактирования задайте STOROZH_API_KEY в окружении сервера. В демо на странице «Политика» введите ключ. Применение проверяет синтаксис, типы действий, ссылки на инструменты и окружения, права и регулярные выражения. POST /policy/reload без тела проверяет файл, с телом принимает yaml_text и версию открытого документа. Конкурирующее изменение отклоняется. Применение через операторский маршрут записывает автора, время и версию в SQLite. При внешнем изменении файла известна его версия, личность редактора файловой системой шлюзу не передаётся. В браузере без ключей доступна локальная демонстрация с просмотром политики.

| Переменная | Назначение |
|---|---|
| STOROZH_VARIANT | B — TF-IDF для речевых актов по умолчанию, C — локальный RuBERT INT8. A для исследований запускается из отдельного архива. |
| ASTRA_POLICY_PATH | Путь к конкурсной политике |
| STOROZH_DB | SQLite журнала и квитанций |
| STOROZH_API_KEY | Ключ оператора |
| STOROZH_CLIENTS_JSON | Сопоставление ключей клиентов с доверенными user_id и role |
| STOROZH_DATASET_KEY | Отдельный ключ для пакетной проверки жюри |

Не задавайте старую STOROZH_ENCODER_DIR при сравнении A/B/C: она включает прежний отдельный эксперимент замены классификатора категории. Кандидаты B/C различаются моделью речевого акта, оба используют одинаковые классификаторы категории и тяжести.

## Проверка файла жюри

В демо загрузите JSONL, CSV или ZIP с датасетом в формате организаторов. POST /v1/datasets/check?format=jsonl&report=true принимает содержимое файла. ## Воспроизведение

~~~powershell
.\.venv\Scripts\python tests/run_all.py
.\.venv\Scripts\python -m experiment.v15.speech
$env:STOROZH_RESULTS_DIR='artifacts/my-v15-scores'
foreach ($v in 'A','B','C') { .\.venv\Scripts\python -m experiment.v15.measure final $v }
~~~

Программа measure вызывает исходный evaluate.py v2.0, проверяет хеши отложенных данных и использует изолированный сервер и временную базу. Пять прогревочных запросов предшествуют каждому последовательному HTTP-прогону. Идентификаторы и поля разметки остаются в оценщике. baseline.json содержит измерения исходной копии v14 и защищён от перезаписи. Публичные dev.jsonl и evaluate.py находятся в artifacts/astra_public. Для отдельной проверки против уже работающего сервера:

~~~powershell
.\.venv\Scripts\python artifacts/astra_public/evaluate.py --data artifacts/astra_public/dev.jsonl --endpoint http://127.0.0.1:8001/v1/check --report dev-report.json
~~~

Для повторного обучения C нужен локальный каталог исходных весов cointegrated/rubert-tiny2 и среда обучения с torch 2.6.0, transformers 4.49.0, onnx 1.17.0 и onnxruntime 1.20.1. Передайте путь к локальному снимку ревизии e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae. Карточка исходного энкодера с указанием MIT включена в experiment/v15/rubert-tiny2-source.md. Готовая INT8-модель с токенизатором входит в app/weights/speech-encoder. Для оценки готовых A/B/C повторное обучение не требуется.


Браузерный тест использует Node 22+ и локальный Chrome. Путь к браузеру можно задать переменной CHROME, к Python — PYTHON. Отчёты по доменам, матрицы решений, recall по категориям, задержки и память приведены в experiment/v15.

## Проверка поставки

Версию с опциональной моделью вложений собирает команда `python -m experiment.v16.release`. Она создаёт `artifacts/AI-Storozh-v16-CPU.zip` из сохранённой основы v15, актуального рабочего кода, локальных весов и материалов эксперимента. Для повторной сборки и парного сравнения положите оригинальный `AI-Storozh-v15-CPU.zip` в `artifacts/`. Для запуска самой v16 достаточно распаковать новый ZIP.

Следующие команды относятся к распакованной исторической поставке **v15**.

Команда python -m experiment.v15.release verify сверяет веса, файлы сервиса, публичный оценщик и датасет с SHA256. Команда python -m experiment.v15.release zip формирует artifacts/AI-Storozh-v15-CPU.zip и проверяет его CRC и контрольные суммы. python -m experiment.v15.check_package запускает обе конфигурации из распакованного архива. Полные исторические сторонние CSV для восстановления части базовой линии в ZIP не включены; их исходные контрольные суммы указаны в experiment/external/run.py. Для работы шлюза, финального тематического теста и проверки исключения домена эти CSV не нужны.
