# B v21 · проверка переноса на внешние запросы

На 800 новых запросах v21 приняла 667 верных решений против 574 у v20. До цели в 90% не хватило 53 верных решений. Положительный результат на этой выборке не перенёсся на третий источник и публичный конкурсный набор. Рекомендация для сдачи — сохранить прежнюю конфигурацию. [Полная таблица измерений](METRICS.md)

## Почему v20 ошибалась

Повторный прогон старых 400 запросов через API дал те же 68 пропусков из 200 угроз и 40 ложных блокировок из 200 обычных запросов. У каждого пропуска обученная модель инъекций поставила категорию `none`. В 67 случаях шлюз пропустил запрос по общему пути, в одном распознал учебный вопрос. Медиана оценки ближайшего класса атак составила −0,688 для пропущенных угроз и −0,666 для верно пропущенных обычных запросов. Уменьшение единого порога затрагивает обе группы. Модель речевого акта распознала попытку обхода у 34 из 68 пропущенных угроз и у 23 из 40 ошибочно заблокированных запросов. [Замер базовой версии](baseline-diagnosis.json)

Из 40 ложных блокировок 22 вызваны моделями v20, 17 — старой моделью категорий, одна — действующим запретом политики на операцию. Последняя считается ошибкой по внешней бинарной разметке. Для сервиса с этой политикой это ожидаемый отказ. Среди ложных блокировок встречались литературные задания, просьбы перефразировать текст и вопросы с цитатами. В первом источнике сосредоточились 47 из 68 пропусков и 29 из 40 ложных блокировок. Это объясняет, почему средний показатель скрывал разницу между источниками.

## Данные и обучение

Перед обучением сохранены индексы, контрольные суммы источников и исходная версия кода. Основной тест включает 400 опасных и 400 обычных запросов, поровну от двух исходных англоязычных корпусов в русском переводе. Для калибровки отдельно взяты 260 запросов из тех же источников. Внешние 800 позволяют проверить новые формулировки при знакомом распределении. Для проверки смены источника отдельно зафиксирован англоязычный тест другого автора, 45 опасных и 12 обычных запросов. Номера примеров, метки и названия источников не передаются модели. [Разбиение и SHA256](split.json) · [Третий источник](https://huggingface.co/datasets/ai-mitra/prompt-injection-dataset)

Обучающие классификаторы получили 6 696 других текстов. Это размеченные примеры из нескольких источников, включая обычные русские вопросы, учебные запросы и вредные обращения разных типов. При подготовке данных исключены совпадения и близкие текстовые повторы с контрольными запросами на русском и английском. Фильтр повторов по словам не гарантирует удаления всех свободных переводов или смысловых дублей. [Состав и хеш обучающей выборки](training-data.json) · [Многоязычная коллекция](https://huggingface.co/datasets/RomanKudriavskii/jeff-guard-multilang-dataset) · [Aegis](https://huggingface.co/datasets/nvidia/Aegis-AI-Content-Safety-Dataset-2.0) · [SafeGuard](https://huggingface.co/datasets/jcanode/safeguard-prompt-injection)

Готовый multilingual-e5-small в формате ONNX int8 преобразует текст в вектор. Мы обучили шесть SVM-классификаторов на его представлениях, классификатор на символьных и словесных признаках и модель выбора категории. Логистическая регрессия объединяет их сигналы, оценки v20 и близость к описаниям безопасных и опасных намерений. Веса самого энкодера заморожены. Компонент оценивает самостоятельный текстовый запрос без истории, вложений и распознанной операции по политике. При низкой оценке он может снять только некоторые блокировки обученных моделей. Правила полномочий имеют приоритет. [Реализация модели](../../app/semantic_review.py) · [Параметры выбранной версии](../../app/weights/semantic-review/config.json)

| Кандидат на калибровочных 260 | Верные решения через API | Пропущено угроз | Ложные блокировки |
|---|---:|---:|---:|
| v20 | 179 | 53 | 28 |
| Первая смысловая модель | 189 | 44 | 27 |
| Ансамбль v21 | 216 | 25 | 19 |
| Дополнительные модели фрагментов и похожих вопросов | 214 | 24 | 22 |

Пороги выбирались на калибровочных данных с пятью группированными разбиениями. Для выбранной конфигурации точность на предсказаниях вне своей обучающей группы составила 82,3%. Приведённые выше 216/260 — результат на данных, по которым обучалась итоговая калибровка. Более сложный кандидат поднял задержку p95 с 99 до 160 мс и добавил три ложные блокировки. Проверены также оценки логического следования и нелинейная калибровка. Финальная конфигурация использует линейную калибровку с порогами 0,45 и 0,58. До финальной оценки зафиксированы SHA256 116 файлов. [Выбор конфигурации](runtime-selection.json) · [Манифест](candidate.json)

## Проверка через API

Внешние прогоны v20 и v21 выполнялись последовательно по HTTP на одних запросах после пяти прогревочных вызовов, с доступом к четырём логическим CPU. Обе версии выдали валидные ответы на все внешние запросы. В двух внешних тестах решения были только allow и block. Публичный конкурсный набор также проверяет confirm. Для регрессии на публичном и двух прежних внутренних наборах использованы сохранённые измерения v20 и новый прогон v21.

| Выборка | Точность v20 → v21 | Угрозы с allow | Обычные с block |
|---|---:|---:|---:|
| 800 новых запросов | 71,8% → **83,4%** | 149 → **66** из 400 | 77 → **67** из 400 |
| 57 запросов другого автора | 98,2% → **86,0%** | 1 → **8** из 45 | 0 → **0** из 12 |
| 500 публичных конкурсных примеров | 95,4% → **87,4%** | 1 → **6** из 200 | 20 → **55** из 264 |

На основных 800 запросах доля заблокированных угроз выросла с 62,75% до 83,5%. Сквозная задержка p95 выросла с 55 до 107 мс, максимум v21 составил 201 мс. Парный стратифицированный бутстрэп с группировкой текстовых повторов дал 95%-й интервал прироста точности от +8,7 до +14,7 п. п., интервал самой точности v21 — 80,8–85,9%. Доля ложных блокировок снизилась с 19,25% до 16,75%. Интервал изменения от −6,5 до +1,5 п. п. включает ноль. В первом источнике ложных блокировок стало 42 вместо 63, во втором — 25 вместо 14. Нулевая доля ошибок на 12 обычных запросах третьего источника также имеет большую неопределённость. [Парное сравнение](comparison.json)

На конкурсе ошибки имеют разную цену. На публичном наборе с оригинальным оценщиком v2.0 Score упал с 0,962 до 0,887, точность категории с 87,4% до 79,4%, доля block на опасных high/critical с 99,4% до 97,6%. У внешних наборов есть только бинарная разметка. По ним нельзя оценить точную категорию, high/critical или конкурсный Score. Распределение внешнего теста сбалансировано искусственно, поэтому его точность не является прогнозом для трафика конкретного заказчика. [Конкурсные метрики](final-public.json)

Главный нерешённый вопрос — перенос границы между обсуждением, реальной атакой и другим вредным контентом при смене источника разметки. Более простая внешняя метка «опасно» иногда расходится с решением по роли и контексту. Для следующей итерации нужны согласованно размеченные по конкурсной политике примеры и проверка с исключением целого источника при обучении и калибровке. Приведённые финальные выборки теперь годятся только для регрессии. На них не выбирались пороги следующей версии.

## Воспроизведение

Веса выбранной v21, токенизатор и конфигурация лежат в `app/weights/semantic-review`. При запуске сайта интернет не нужен. API запускается из корня проекта командами из [README](../../README.md). Код 7 включает v20, код 8 — v21.

Для повторного измерения нужны установленные зависимости проекта, исходные файлы конкурса в `artifacts/astra_public` и прежние артефакты v20. Загрузчик исследовательских файлов проверяет контрольные суммы и использует сеть только при отсутствии файла. В каждом повторном прогоне задайте новое имя отчёта. Сохранённые результаты защищены от перезаписи.

~~~powershell
python -m experiment.v21.fetch
python -m experiment.v21.lock
python -m experiment.v21.bench 7 repeat20 test third public blind older
python -m experiment.v21.bench 8 repeat21 test third public blind older
python -m experiment.v21.report
python tests/run_all.py
~~~

`report` строит таблицы исходного зафиксированного сравнения из файлов baseline и final. Сырые счётчики новых прогонов находятся в repeat20-*.json и repeat21-*.json. Полный локальный набор тестов прошёл, включая четыре проверки новой модели, её автономной загрузки и приоритета политики.

Для повторного обучения используйте отдельную рабочую копию с зафиксированным split.json. Подготовьте `artifacts/transfer-v20-fit.json` по [инструкции v20](../v20/REPORT.md). Для чтения архивов при подготовке использовался pyarrow 24.0.0. В среде сервиса он не требуется. Из корня копии выполните команды ниже. Скрипт подготовки сообщает хеш выборки. Архивный `baseline-cal.json` уже существует, а для подготовки признаков калибровки нужно создать `artifacts/v21-baseline-cal.npz`. Первая команда замера с новым тегом создаёт его под новым именем, которое копируется в ожидаемый путь. Оригинальные запечатанные файлы оставьте в исходной рабочей папке.

~~~powershell
python -m experiment.v21.fetch --training
python -m experiment.v21.bench 7 rebuild cal
Copy-Item artifacts/v21-rebuild-cal.npz artifacts/v21-baseline-cal.npz
python -m experiment.v21.prepare
python -m experiment.v21.encode
python -m experiment.v21.train
python -m experiment.v21.probes
python -m experiment.v21.stack
~~~

Эти шаги обучают выбранный ансамбль. Скрипты bags, lookalikes, refine, calibration и select_runtime воспроизводят дополнительные эксперименты отбора. При иной платформе или версии библиотеки байтовая сериализация весов может отличаться. Для точного повторения измерений используйте поставленные веса. [Версии библиотек](../../requirements.txt)
