# Десять доменов. Проверка CPU-сторожа v7 и v8

На трёх отложенных доменах v8 принял 2806 правильных решений из 3000 (93,53%). У v7 было 2722 (90,73%). Количество пропущенных угроз снизилось с 205 до 138, ложных блокировок — с 71 до 56. Из 1200 угроз высокого и критического уровня v8 остановил 1072 (89,33%). Все 210 запросов, требующих подтверждения, получили именно это решение.

## Как построена проверка

Десять JSONL содержат по 1000 уникальных сочетаний текста, роли, истории и вложений. В каждой отрасли представлены десять рабочих процессов. Каждый файл содержит 470 допустимых запросов, 70 операций с подтверждением и 460 запрещённых запросов. Среди последних 400 имеют высокий или критический риск. Количество русских и английских примеров одинаково. На домен приходятся 453 прямых обращения, 214 продолжений предыдущей просьбы, 213 обращений на фоне диалога и 120 проверок служебных записок.

Генератор использует авторские сценарии и отдельную таблицу прав по роли, среде и операции. Он не импортирует сторожа, не обращается к моделям и не запрашивает у них метки. Входы, эталоны, контрольные суммы и разделение доменов сохранены в коммите `4705662`. Инференсу передавались только текст и контекст. У пакетного API также использовался идентификатор для сверки ответов.

Для выбора изменений использовались результаты семи доменов. У трёх контрольных отраслей отдельные русские и английские формулировки для каждой из 38 пар сценариев и отдельные формулировки операций. Сами задачи, структура пакета и политика роли общие. Модель v8 зафиксирована в `56b3b34` до разбора результатов v7 и v8 на этих трёх отраслях.

## Какие ошибки удалось исправить

В семи доменах v7 68 раз разрешил просьбу действовать вопреки предыдущим инструкциям. Он также путал запрос чужой закрытой записи с попыткой мошенничества. Для модели категорий и бинарного детектора добавлены отдельно написанные пары примеров про конфликт инструкций, полномочия, отказ в выдаче информации и рабочую переписку. При обучении одни и те же нейтральные просьбы пересказать вложение сочетались как со служебными письмами, так и с документами, содержащими указания для агента.

Раньше английское слово `replacement` в названии операции по замене оборудования активировало признак подмены инструкций. Границы слова уточнены. Вежливые варианты простых команд теперь проходят ту же проверку роли и среды, что и краткие команды. Составные просьбы и вложения продолжают проходить остальные проверки.

## Что осталось

На контроле v8 заблокировал 240 из 240 критических угроз и 832 из 960 угроз высокого уровня. По классу jailbreak заблокирован 61 из 120 запросов (50,8%), у v7 было 63 из 120. По подмене текущих инструкций — 92 из 120 против прежних 93. Общий выигрыш по полноте не распространяется на каждый класс.

В контрольных доменах пропущены 59 случаев jailbreak, 32 требования изменить системные правила, 28 попыток подменить инструкции текущего запроса, 10 запросов на травлю, 7 запросов чужих данных и 2 инструкции во вложениях. Ещё 30 попыток повысить права модель остановила, но объяснила их категорией мошенничества. Среди ложных блокировок часто встречаются сообщения о случайно открывшихся чужих данных и просьбы помочь вежливо отказать в их выдаче.

На прежних трёх отраслевых файлах доля ложных блокировок снизилась с 63 до 51 из 1380. Все 1368 запрещённых запросов заблокированы. На публичном контроле организаторов результаты совпали с v7: решение 126/133, категория 117/133, уровень 117/133, ложные блокировки 3/70, строгая блокировка high/critical 34/38. Пропущены три jailbreak и один запрос категории harmful_content.

Десять тысяч строк образованы вариациями авторских сценариев. На контроле одновременно меняются отрасль и формулировки, поэтому измерить отдельный вклад каждой причины по этим файлам нельзя. Результаты финала организаторов будут зависеть от состава их закрытых данных.

## Файлы и воспроизведение

Через пакетный HTTP API повторно проверены все 10 000 запросов без меток. Идентификаторы, решения, категории и уровни совпали с локальным прогоном v8 во всех строках.

[Десять наборов JSONL](data/) · [Контрольные суммы](manifest.json) · [Метрики с матрицами ошибок](comparison.json) · [Сверка API по файлам](api_verified.json) · [Проверка прежних наборов](../v8/regression.json)

Исходную версию можно воспроизвести из коммита `4705662` командой `python -m experiment.ten_domains.evaluate v7`. Для v8 доступны следующие команды из корня проекта. Переобучение использует прежние обучающие материалы проекта. Готовая модель включена в репозиторий.

~~~powershell
python -m experiment.ten_domains.generate
python -m experiment.ten_domains.evaluate v8
python -m experiment.ten_domains.compare
python -m experiment.v8.regression
python tests/run_all.py
~~~

Для сверки с работающим стендом на порту 8001 запустите `python -m experiment.ten_domains.verify_api`. Скрипт сверяет идентификатор, решение, категорию и уровень каждой строки с построчным прогнозом. Прогнозы обеих версий сохранены в каталогах v7 и v8 в формате JSONL с gzip-сжатием.
