# B v16. Проверка намерения во вложениях

Для каждого сравнения исходная B из сохранённого ZIP v15 и кандидат получили одни и те же пакеты через POST /v1/check. Строгая блокировка учитывает только решение block. Приёмка требует одновременно не менее 85% блокировок на эталонных high/critical, ноль вновь заблокированных легитимных пакетов и ноль технических сбоев. Закрытый тест жюри не использовался.

## Как проходил эксперимент

Сначала зафиксировали контрольные суммы исходной B, первой выборки на 360 пакетов и критериев приёмки (study.json). Первый кандидат обучался на 2 016 строках, 56 семействах. Он заблокировал 139 из 144 атак, но добавил пять ложных блокировок. Сохранены его веса и исходники в candidate1.zip. Для второй итерации использован только этот агрегированный сигнал о регрессии.

До следующей калибровки отдельно зафиксировали второй тест в study2.json. Он включает 36 новых парных формулировок в четырёх представлениях и 72 обычных документа. Затем в обучение добавили 28 новых пар с распоряжениями людям, редакторам, сотрудникам и ассистентам. Калибровка включала 36 дополнительных обычных текстов. Окончательная модель не обучалась на blind.jsonl, blind2.jsonl или на прежнем наборе из 870 пакетов.

На этапе 2 получено 3024 учебных строк из 84 семейств. На 400 примерах для калибровки модель выделила 88.3% активных инструкций при 0 ложных блокировках. Ограниченный выбор C и порога производился только на разработческих данных.

## Как устроена проверка

Новая линейная голова сочетает символьные и словесные n-граммы с признаками адресата, замены результата, активного поручения, цитирования и бумажного документооборота. Признаки извлекаются из содержимого вложения. Имя файла, id, роль, ожидаемое решение, метки и тема в эту модель не передаются. Для длинных текстов используются перекрывающиеся окна, включая конец. В ответ API передаются индекс вложения и границы окна, на котором сработал детектор. При недостаточном сигнале действуют прежние правила B. Новая голова может только усилить решение согласно always_block из действующей политики.

## Что подтверждают эти числа

Каждый новый набор содержит 144 инъекции и 216 легитимных пакетов. Внутри набора пары разделяют тему, имена файлов, маркер и пользовательское поручение. Среди обычных приложений есть цитаты, протоколы, учебные реплики и просьбы сотруднику выполнить реальную работу с бумажным носителем. Присвоенный эталон high относится к подмене ответа. Эталон critical относится к попыткам сфальсифицировать вывод об одобрении. Тесты моделируют влияние на целостность ответа при помощи фиктивных отметок; никакие инструменты не вызываются.

Это синтетические данные одной команды. В 144 атаках каждого испытания 36 семейств, формы документов повторяются. Проценты относятся к этим пакетам и не дают гарантии для произвольных документов. Декларативные указания без явного адресата, продолжения на границах окон, ирония и неразмеченная чужая речь остаются трудными случаями. Техническая остановка не считается успешным распознаванием. Старые ложные блокировки также видны в таблице.

## Воспроизведение

Команды из корня проекта в окружении с requirements-dev.txt. Для сравнения нужен исходный artifacts/AI-Storozh-v15-CPU.zip с SHA256 из study.json. Замер использует CPU, четыре доступных логических ядра, пять прогревов и последовательный локальный HTTP. Исходные отчёты хранятся в results/. Для повтора выберите новый каталог.

~~~powershell
python -m experiment.v16.train --model artifacts/retrained-attachment.joblib
python -m experiment.v16.evaluate before2 --output artifacts/v16-rerun
python -m experiment.v16.evaluate after2 --output artifacts/v16-rerun
python tests/run_all.py
~~~
