# B v22 · первые три раунда

У v21 на публичном наборе изменились 42 решения относительно v20. На 35 обычных запросах новый слой добавил блокировку, на шести угрозах снял верную блокировку и на одной угрозе исправил пропуск. Среди 35 добавленных ложных блокировок 30 получили категорию prompt_injection, пять — harmful_content. Наблюдение получено сопоставлением решений по одним и тем же примерам. [Ответы v21](v21-public.json) · [Ответы v20](../v20/final-public.json)

Для первого кандидата обучили модель категорий на 7 930 текстах и добавили сигнал специализированного многоязычного энкодера. Второй получил три дополнительных классификатора на смысловых представлениях и 1 727 дополнительных текстов. Третий использует также скрытое представление энкодера защиты, две обученные на 2 269 примерах головы и калибровку по группам близких формулировок. Исходные нейросетевые энкодеры оставались замороженными. Числа разных раундов частично перекрываются. [Обучение](training.json) · [Второй раунд](second-training.json) · [Третий раунд](third-training.json)

Первые два промежуточных набора использовались для выбора следующего варианта. В них возможны совпадения с архивами до v15. Дополнительная проверка происхождения перед финалом охватила обе языковые версии 5 354 исторических внешних строк, обучающие данные и предыдущие наборы. В первоначальном финальном списке обнаружилось 115 пересечений. После исключения пересечений и пополнения из независимых строк осталось 644 запроса. Для третьей промежуточной проверки применён тот же фильтр. [Исходное разбиение](panels.json) · [Аудит до финальной оценки](audited.json)

| На финальных данных | Точность v21 → v22 | Угрозы с block | Обычные с block |
|---|---:|---:|---:|
| Внешние 644 | 78,7% → 88,2% | 241 → 278 из 311 | 67 → 43 из 333 |
| Публичные 500 | 87,4% → 88,6% | 194 → 199 из 200 | 55 → 54 из 264 |

На внешнем наборе парный 95%-й интервал прироста точности составил +6,8…+12,3 п. п. На публичном наборе почти все лишние блокировки сохранились. Для следующего раунда обучили отдельную модель пересмотра решения. [Метрики v22 по источникам и конкурсному оценщику](metrics.json) · [Последующий эксперимент](../v23/REPORT.md)

Веса и токенизатор работают локально. Специализированный ONNX основан на открытом Horizon-Labs/prompt-injection-guard-small, дополнительно использовался энкодер e5 из v21. Опубликованные автором тесты предобученного защитного энкодера частично совпадают по названиям с нашими внешними источниками. Мы удаляли пересечения с известными обучающими данными проекта. Полное отсутствие исторического знакомства чужих энкодеров с этими корпусами проверить нельзя. [Модель и происхождение данных](https://huggingface.co/Horizon-Labs/prompt-injection-guard-small) · [Исходные тесты](https://huggingface.co/datasets/Horizon-Labs/prompt-injection-eval-suite) · [Авторские примеры другого источника](https://huggingface.co/datasets/edithngalame/prompt-injection-en-es)

В локальном API v22 включается режимом B и значением 9 у STOROZH_ATTACHMENT_INTENT. Для повторных проверок из текущего дерева используйте команды в отчёте следующего раунда. Историческое состояние общего кода v21 сохранено в v21-overlay.zip, v22 — в соседнем v23/v22-overlay.zip.
