# v4. Проверка качества и требований комплекта «Астра» v2.0

## Какие цифры сопоставимы

В таблице accuracy означает долю точных совпадений с эталоном. Решение и основная категория оцениваются отдельно. Строгий recall учитывает только block на опасных примерах high/critical.

| Набор и назначение | Решение | Категория | High/critical block | p95 HTTP |
|---|---:|---:|---:|---:|
| Новые формулировки, 92, проверка после фиксации весов | 85/92 (92,4%) | 82/92 (89,1%) | 54/54 | 39,3 мс |
| Public/dev, прежние 133 примера для разбора ошибок | 125/133 (94,0%) | 116/133 (87,2%) | 34/38 (89,5%) | 41,4 мс |
| Прежние 1000 синтетических сценариев, регрессия | 977/1000 | 968/1000 | 370/370 | 39,4 мс |

Публичные 133 строки исключены из обучения весов, но использованы при разработке признаков, правил и дополнительных примеров. Раньше на них версия v3 получила 107/133 верных решений, 84/133 верных категорий, 38/38 строгих блокировок и 18/70 ложных блокировок обычных запросов. У v4 ложных блокировок 4/70, при этом пропущены четыре серьёзные угрозы.

В разработку v4 вошли 367 строк public/dev и семантические сценарии банковского раздела прежней синтетической тысячи. Старые синтетические результаты используются только как регрессионные. Тексты training.txt, benign_context.txt, примеры v2 и признаки описаны в train.py и app/intent_features.py. Модели получают только содержимое входного пакета. Права роли определяются по YAML при обработке запроса. Обучение и проверка выполнялись локально без внешних LLM.

Файл challenge.jsonl зафиксирован до обучения v4. SHA-256 равен 79f05a040e4e13bdc513092976277bc043558ee5ee74dd9b9904845ea6b9c3ea. В нём 68 авторских смысловых примеров (включая историю и вложения) и 24 комбинации роли, окружения и действия. Формулировки новые; тематика и правила соответствуют заданию. Авторская разметка, общие типы намерений и небольшой размер ограничивают независимость оценки. Классификатор текста сам по себе верно выбрал категорию в 62 из 68 смысловых случаев и 74 из 92 в целом. Полный сервис правильно ответил на 7/7 confirm; 7/31 обычных запросов ошибочно заблокированы. Среди ошибок есть чтение журнала и безопасный вопрос о случайно открывшихся чужих данных. Два запроса с инструкцией во вложении остановлены с неверной основной категорией.

## Сверка с ТЗ

| Требование | Что проверено и что остаётся |
|---|---|
| HTTP API и автономность | POST /v1/check принимает запрос и контекст. Веса лежат в репозитории, CPU-инференс использует scikit-learn. История evaluator не накапливается между строками. 1225 ответов трёх прогонов без невалидных результатов и тайм-аутов. |
| Политика и полномочия | Права ролей и окружений загружаются из security_policy.yaml. Тест меняет правило SRE и наблюдает другое решение без перезапуска. Распознавание операций частично основано на правилах в коде. Общий порог v2 читается из policy.yaml. Разбор неоднозначного окружения требует более ясного объяснения. |
| Контекст и классификация | Анализируются текущий текст, история и содержимое вложений. Возвращаются решение, категория, уровень риска и причина. Уровень риска пока грубый: для block выдаётся high, в том числе для эталонных critical. Верная блокировка и точность уровня риска — разные измерения. |
| Демо и доставка | Локальная форма показывает роль, историю, вложения и результат. Тесты подтверждают отдельное согласование, запрет отправки до подтверждения, запрет block и повторной доставки. Демополучатель фиксирует факт получения. |
| Журнал и конфиденциальность | Конкурсный журнал сохраняет идентификатор, время, роль, категорию, решение, задержку, версию политики и состояние доставки. Исходный пакет в нём заменён отпечатком. Старый операторский маршрут имеет отдельное хранилище; внешний доступ к нему потребует отдельной проверки. |
| Ресурсы | После пяти прогревочных запросов использован официальный evaluator v2.0, запросы последовательные. На рабочем сервере Windows после запуска и трёх демонстрационных запросов измерен PeakWorkingSet64 около 179,3 МиБ. Это замер процесса на коротком сценарии. Пиковая RAM под полной нагрузкой, лимит 8 vCPU и VRAM на машине организаторов отдельно не подтверждены. |
| Комплект сдачи | Есть исходники, веса, запуск, политика, отчёты. Для ключевой библиотеки модели закреплена версия; часть зависимостей задана диапазонами. Внешний доступ для экспертов и презентация команды в рамках этой проверки не подтверждены. |
| Бонусы | Условия скорости и качества CPU достигнуты на указанных локальных замерах. Бонус определяют организаторы. В прежнем интерфейсе есть административные функции; полный набор бонусных критериев по конкурсной политике и изолированным сессиям не подтверждён. |

## Воспроизведение

Из корня проекта с распакованными публичными данными и установленными requirements.txt:

~~~powershell
python -m experiment.v4.train
python tests/run_all.py
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
~~~

После прогрева сервера пятью примерами из public/dev в другом терминале:

~~~powershell
python artifacts/astra_public/evaluate.py --data experiment/v4/challenge.jsonl --endpoint http://127.0.0.1:8001/v1/check --report artifacts/astra_public/repeat-v4-report.json
~~~

Файлы fresh-report.json, dev-report.json и regression-report.json содержат исходные результаты HTTP-прогонов.
