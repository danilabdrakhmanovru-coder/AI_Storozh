# B v20. Распознавание инъекций и jailbreak на CPU

На новых 12 темах v20 правильно выбрала действие в 441 из 480 случаев (91,9%). Из 240 угроз 235 заблокированы, 5 получили allow. Из 240 обычных запросов 34 заблокированы ошибочно. Категория верна у 91,0% всех запросов. Для v19 соответствующие числа составили 413, 212, 28 и 39. На публичной выборке организаторов число лишних блокировок выросло с 11 до 20 из 264. На прежних 120 внешних запросах правильных решений стало 90 вместо 93. Конкурсную конфигурацию по умолчанию сохранили.

## Обучение и решения сервиса

В режиме 7 работают прежние проверки роли и политики, каскад v19 для вложений и дополнительные обученные линейные SVM. Первая модель учитывает слова, фрагменты слов и начало высказывания. Она обучена на 2 615 различных строках, включая производные с одним случайным пропуском, повтором или перестановкой буквы. Вторая оценивает фрагмент документа вместе с соседними предложениями. При обучении использованы 16 916 примеров окон, в том числе одинаковые распоряжения как действующие указания и как цитаты из старого отчёта. Для бинарного голоса использованы 3 161 строка, включая 546 исходных обучающих примеров deepset. Эти количества частично пересекаются. Названия доменов, контрольные метки и идентификаторы в векторизаторы не передаются. [Обучающие источники и контрольные суммы](training.json), [карточка deepset](https://huggingface.co/datasets/deepset/prompt-injections).

У ответов модели есть привязка к источнику. Если сохранились координаты в исходном вложении, сигнал содержит смещение. Режим отдельно распознаёт односоставный информационный вопрос о политике или настройке помощника. Этот голос может снять блокировку старой модели только при отсутствии истории, вложений, решения по полномочиям и сильного сигнала основного классификатора. Явные запреты и неизвестная роль проверяются раньше. API по-прежнему только оценивает запрос. Для инференса достаточно локальных файлов проекта.

## Методика

До обучения зафиксированы наборы из 4 тем для разработки и 12 тем для окончательной проверки. В каждой теме есть пять пар намерений. Каждая пара содержит угрозу и обычный вопрос или документ, у каждого текста — четыре формы. Пересказы написаны отдельно. Опечатка вносится в одно случайно выбранное слово фиксированным генератором. Запросы и документы на русском и английском, часть контекстов смешанная. История включает явное продолжение предыдущей просьбы. Длина наполнения вложений на новом тесте от 480 до 16 000 символов. Для 32 000 символов использован отдельный исторический стресс-тест. [Контрольные суммы данных](data-seal.json), [состав зафиксированной конфигурации](candidate.json).

На 160 запросах разработки точность решения менялась от 128 у v19 до 135, 143, 149 и 151 правильного решения у последовательных вариантов. Первая итерация увеличила число ложных блокировок с 10 до 14. Обучение на контрастных вопросах и отдельная модель для процитированных инструкций сократили их до 8 в итоговой конфигурации. Порог для документов выбран по четырём темам разработки и отдельным архивным контрастным парам. Финальные 480 запросов не использовали для выбора порогов или исправления ошибок. Точные нормализованные пересечения нового теста с размеченными строками обучения не обнаружены. [Подбор порога](calibration.json).

Метрики получены на последовательных вызовах HTTP с пятью прогревочными запросами на отдельном локальном порту, с ограничением процесса четырьмя доступными логическими CPU. Запрос содержит только пользовательский текст и контекст. Сбой или превышение бюджета считается ошибкой. Оценку стоимости рассчитывает неизменённый оценщик организаторов v2.0. Веса не передавались в работающий экземпляр демонстрационного сайта.

## Границы результата

Из 480 запросов получилось 60 связанных пар ситуаций. Варианты одной пары, стилистическое сходство одного автора и повторяющийся фон длинных документов ограничивают перенос результата. Срез с опечаткой проверяет одиночную ошибку. Проверка не охватывает произвольные многошаговые сценарии, целенаправленную адаптацию атак или все возможные способы записи. На целевой выборке нет эталонного confirm. Для решений по полномочиям приведены отдельные измерения на конкурсных данных.

В новой выборке часть выигрыша связана с прямой подменой задачи. Для вложений заблокировано 47 из 48 угроз против 43 из 48 прежде, при этом выросло количество ложных блокировок сопоставимых документов с 0 до 4. На 32K p95 составляет 1,34 с. Порог 0,5 с проверялся на обычной смеси запросов. Машинные переводы во внешних наборах размечены как safe/unsafe, поэтому для них сопоставлены решения, без приписывания конкретной категории или уровня риска. Закрытые данные организаторов в работе не участвовали.

## Ещё одна попытка повысить перенос между источниками

После замера на 120 внешних запросах подготовлена свежая выборка из 400 других запросов. В каждом из двух источников по 100 положительных и 100 отрицательных примеров. Данные и критерий принятия зафиксированы до обучения следующей модели. Из нового корпуса обучения исключались текстовые совпадения и существенные перекрытия последовательностей слов с контрольными фразами и их английскими оригиналами. [Протокол выбора](transfer-plan.json).

Отдельный двуязычный SVM обучен на 10 976 текстах. В положительном корпусе представлены шесть техник, включая подмену инструкций, игры с ролями, разбиение текста и обфускацию. Обычные вопросы взяты из прошедших рецензирование корневых обращений OpenAssistant и из контрастных примеров проекта. Для разработки целиком отложены два происхождения положительных примеров, обычные обращения разделены по авторам. На этих данных сбалансированная точность составила 90,9%. Русская и английская формы одного обращения связаны. Метка «обычное обращение» для OpenAssistant приближённая, поскольку проект размечал качество сообщений и их приемлемость. [Russian Prompt Injection Dataset](https://huggingface.co/datasets/dmtrdr/russian_prompt_injections), [OpenAssistant OASST1](https://huggingface.co/datasets/OpenAssistant/oasst1), [веса и параметры опыта](transfer-lock.json).

| Новые внешние запросы | Правильное решение | Угрозы с allow из 200 | Обычные с block из 200 |
|---|---:|---:|---:|
| B v19, фактическое решение API | 305/400 (76,25%) | 73 | 22 |
| B v20, фактическое решение API | 292/400 (73,0%) | 68 | 40 |
| Дополнительный SVM отдельно | 250/400 (62,5%) | 59 | 91 |
| B v20 с дополнительным голосом | 253/400 (63,25%) | 35 | 112 |

Совместное решение рассчитано в испытательном процессе по реальному ответу API и голосу дополнительной модели на том же тексте. Оно сохранило все исходные блокировки. Выигрыш в 33 остановленные угрозы сопровождался 72 дополнительными ложными блокировками. Точность v20 по отдельным источникам составила 62% и 84%. Сильная зависимость от источника измерена; возможное объяснение — различия стиля между обычными вопросами и атакующими корпусами. Для проверки этой причины нужна сопоставимая разметка обоих классов внутри каждого источника. [Итоги по источникам](transfer-result.json).

Для конкурса оставлен ранее выбранный режим. B v20 доступна для испытаний через API. Второй SVM сохранён как исследовательский вариант. Все 12 файлов регрессионных тестов проекта прошли, в том числе новые проверки роли, политики, опечатки и источника обнаружения.

## Запуск v20

Из корня репозитория, PowerShell, в окружении с зависимостями из requirements.txt:

~~~powershell
$env:STOROZH_VARIANT='B'
$env:STOROZH_ATTACHMENT_INTENT='7'
python -m uvicorn app.main:app --host 127.0.0.1 --port 8010
~~~

В проекте с уже установленным окружением вместо python можно вызывать .\artifacts\v15-clean\Scripts\python.exe. Для сравнения v19 используется значение 6. Шлюз получает запрос в POST /v1/check.

## Повтор измерений

Установить requirements-dev.txt с зависимостями тестов. Для работы с parquet при подготовке данных использовался pyarrow 24.0.0 в отдельном окружении. В сервис эта зависимость не входит. В папке artifacts/astra_public нужны исходные evaluate.py и dev.jsonl. Файлы benchmark1.csv и benchmark2.csv берутся из версий, указанных в experiment/external/manifest.json. Отчёты новых прогонов сохранять с новым именем.

~~~powershell
python tests/run_all.py
python -m experiment.v20.evaluate 6 repeat-v19 dev blind public older external
python -m experiment.v20.evaluate 7 repeat-v20 dev blind public older external
~~~

Для восстановления весов с нуля выполнить в отдельной копии проекта:

~~~powershell
Invoke-WebRequest 'https://huggingface.co/datasets/deepset/prompt-injections/resolve/4f61ecb038e9c3fb77e21034b22511b523772cdd/data/train-00000-of-00001-9564e8b05b4757ab.parquet' -OutFile artifacts/deepset-v20-train.parquet
python -m experiment.v20.convert_deepset
python -m experiment.v20.train
python -m experiment.v20.calibrate
~~~

calibrate использует сохранённые исходные решения dev2-dev.json. Повторное обучение в другой версии библиотек может изменить байты сериализации. lock.py запечатывает новую конфигурацию один раз. Для исторического аудита исходные app/contest.py и app/main.py v19 сохранены в v19-overlay.zip. [Точные версии библиотек сервиса](../../requirements.txt).

Для отдельного двуязычного эксперимента в свежей копии подготовить исходные файлы по зафиксированным версиям. Скрипт подготовки использует pyarrow 24.0.0. Новые отчёты с теми же именами следует создавать в отдельной копии, сохранив ранее запечатанные результаты.

~~~powershell
Invoke-WebRequest 'https://huggingface.co/datasets/dmtrdr/russian_prompt_injections/resolve/2bb249ed6b692f258ac9a369015aeafe1f011fc7/dataset.json' -OutFile artifacts/ru-injections-train-v20.json
Invoke-WebRequest 'https://huggingface.co/datasets/OpenAssistant/oasst1/resolve/fdf72ae0827c1cda404aff25b6603abec9e3399b/data/train-00000-of-00001-b42a775f407cee45.parquet' -OutFile artifacts/oasst-v20-train.parquet
python -m experiment.v20.transfer_sources
python -m experiment.v20.transfer train
python -m experiment.v20.transfer evaluate --output experiment/v20/repeat-transfer.json
python -m experiment.v20.transfer baseline --output experiment/v20/repeat-baseline.json
~~~
