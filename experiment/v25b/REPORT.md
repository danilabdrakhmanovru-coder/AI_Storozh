# Проверка ограниченной поправки к оценке угрозы

У первой v25 внешняя частота ложных блокировок снизилась с 41,5% до 15,5%, а блокировка угроз упала с 92% до 77%. На PIarena исходный энкодер верно распознал 38 из 46 пропущенных угроз. Во всех 46 случаях текст был прочитан целиком. Дополнительная модель, обученная на различии адресатов, присваивала естественному справочному тексту слишком большой отрицательный вес. [Разбор старых 67 случаев и первой v25](../v25/REPORT.md) · [Сигналы отдельных моделей](../v25/transfer-audit.json)

Во втором варианте масштаб поправки обучен на 405 документах разработки и 255 дополнительных документах. Дополнительные источники — английские письма, таблицы, примеры кода BIPIA, LLMail и справочные абзацы SQuAD. Проверка параметров объединения проводилась с исключением целых групп по источнику или области. Веса предыдущих классификаторов фиксированы. Сильный сигнал энкодера теперь может измениться лишь на ограниченную величину. Текст, роль и исходные правила полномочий обрабатывает тот же сервис. [Состав данных](calibration-index.json) · [Выбор параметров](training.json)

До обучения поправки отдельно зафиксированы 320 внешних документов. У каждого из двух источников по 80 угроз и 80 обычных документов. Исключались совпадения и близкие фрагменты с первой панелью, прежними данными и обучением. Проверка на первых 400 после их вскрытия используется для регрессии. Предобученный энкодер и внешние корпуса связаны общим издателем, а скрытый тест организаторов недоступен. [Новая панель](holdout.json) · [Контрольные суммы конфигурации](candidate.json)

На новых 320 блокировка угроз 93,1%, 95%-й интервал 88,1%–96,1%. Ложные блокировки 16,2%, интервал 11,3%–22,7%. Условие публикации по точечным оценкам не выполнено.

Из 67 старых ошибок исправлено 55. У тематических пар оба решения правильны в 30/32 случаях. Одна и та же нейтральная просьба о пересказе и та же роль использованы для каждой пары. На четыре пары в области приходится большая неопределённость. Приведённые оценки относятся к одному вложению, новым текстам известных внешних источников и восьми авторским темам. На уровне правил возникло 14 из 26 ложных блокировок, в том числе 10 по правилу jb_dan. Сам классификатор адресата указан как причина в 4 случаях. Остальные относятся к прежним моделям и возврату к предыдущему конвейеру. Метки, полученные после итогового прогона, в обучение не добавлялись.

Все 17 файлов регрессионных тестов прошли. Отдельно проверены ограничения поправки, обработка длинного текста с непокрытым фрагментом и невозможность снять запрет YAML, даже если его имя совпадает с именем статистической проверки. [Журнал тестов](tests.log)

## Воспроизведение

В подготовленном окружении с зависимостями проекта и восстановленными внешними входами v24 используйте следующие команды. Новый тег сохраняет прежние отчёты.

~~~powershell
python -m experiment.v25b.lock
python -m experiment.v25b.bench 13 repeat fresh external historic control public
python tests/run_all.py
$env:STOROZH_VARIANT="B"
$env:STOROZH_ATTACHMENT_INTENT="13"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8013
~~~

Для повторения обучения в отдельной копии после подготовки v25 выполните python -m experiment.v25b.fetch, python -m experiment.v25b.calibration_data, python -m experiment.v25b.train encode и python -m experiment.v25b.train fit. Для преобразования parquet нужен pyarrow. Проверку HTTP проводили на четырёх логических CPU последовательно после пяти прогревочных запросов. Интернет использовался для получения исходных корпусов исследования. Во время оценки и работы агент обрабатывает запросы локально.
