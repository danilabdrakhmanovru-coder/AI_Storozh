# Контекст правила jb_dan во вложениях

На 426 новых документах сам обработчик остановил 212/213 (99.5%) угроз. Ложные блокировки снизились с 33/213 (15.5%) до 25/213 (11.7%). Допустимый максимум на этой выборке — 21 обычный документ. В полном прогоне новой версии через HTTP было 405 технических отказов. Результаты API и качества распознавания приведены отдельно.

В прежней проверке десять легитимных документов получили block по jb_dan. Во всех десяти встретился английский корень jailbreak. Правило завершало проверку до классификации адресата. Четыре документа предупреждали об инцидентах или объясняли, как о них сообщить, три разъясняли термины, ещё три использовали термин в учебном материале или требованиях к квалификации.

В режиме B/13 при одном вложении и изолированной просьбе о разборе документа лексическое совпадение может уступить решению существующей модели об адресате. Для этого нужен вывод reference по полностью просмотренному документу. Прямые команды смены режима, отдельные кодированные совпадения, неоднозначные и частично просмотренные документы сохраняют блокировку. После снятия одного совпадения продолжаются остальные проверки политики, источников и моделей. Веса и пороги взяты из v25b.

## Новая внешняя проверка

426 документов, по 213 на класс. Перед изменением кода зафиксированы индексы и контрольные суммы источников. Известные документы обучения, разработки и прошлых проверок исключались фильтром совпадений и пересечения шинглов. По каждой коллекции число документов обоих классов одинаково. Первая группа из 28 новых записей вошла в общие 426. У каждого запроса одна и та же роль и просьба о пересказе. Эталон задаёт источник, в API переданы только запрос и контекст.

Буквальный маркер jb_dan встретился в 9 новых обычных документах и 1 опасных. На этом срезе ложных блокировок 0 → 0, заблокированных угроз 0 → 0.

Для новой версии 95%-й интервал Уилсона по доле остановленных угроз равен 4.7%–11.9%, по ложным блокировкам — 0.0%–1.8%. Оценка интервала приближённая, внутри источника возможны тематически близкие документы.

Из угроз получили allow 0, confirm 0, техническую ошибку 197. На обычных документах было 0 лишних confirm и 208 технических отказов. С учётом отказов число обычных документов, для которых проверка завершилась блокировкой либо ошибкой, равно 208/213 (97.7%). Любая техническая ошибка закрывает условие публикации. Оба прогона в сумме различаются по исходу в 0 случаях.

По всем HTTP-ответам, включая отказы, p95 составила 2683 → 2686 мс, максимум 2773 → 2816 мс. Каждому из двух экземпляров назначены четыре отдельных логических CPU на общей машине. Документы подавались последовательно внутри каждого экземпляра. Перед замером отдельно загружены модели на одном нейтральном вложении и выполнены пять прогревочных запросов. При массовых отказах p95 отражает преимущественно время ожидания до отказа.

На публичных 500 исход решения изменился в 0 случаях относительно сохранённого прогона B/13.

Условие публикации по точечным оценкам не выполнено.

## Без тайм-аута HTTP

Вызов тех же правил и моделей внутри одного процесса на тех же документах дал блокировку угроз 212/213 (99.5%) → 212/213 (99.5%), ложные блокировки 33/213 (15.5%) → 25/213 (11.7%). Из десяти разобранных документов allow получили 10. Это отдельная оценка качества распознавания, исключающая сбои транспорта и перезапуски рабочего процесса. Критерий публикации проверялся по HTTP.

В подвыборке с маркером jb_dan число обычных документов равно 9, число угроз — 1. Ложных блокировок стало 1 вместо 9. Обе версии обнаружили единственную угрозу. Одного положительного примера недостаточно для вывода о полноте распознавания всех атак этого типа.

95%-е интервалы Уилсона для самого обработчика составляют 97.4%–99.9% по блокировке угроз и 8.1%–16.8% по ложным блокировкам.

## Границы проверки

Источники предоставляют в том числе синтетические документы. Происхождение или состав предобучения исходного энкодера полностью неизвестны. Проверка относится к одному вложению до 12 000 символов, стандартной роли и просьбе о пересказе. Публичное сравнение и прежние десять ошибок считаются отдельно от нового теста. Оценки относятся ко всему сервису и зависят от состава источников. Для редких классов документов одной общей доли мало.

Тексты из внешних корпусов остаются в локальном кэше. Индексы и контрольные суммы позволяют восстановить выборку. [Коллекции документов Horizon Labs](https://huggingface.co/datasets/Horizon-Labs/prompt-injection-eval-suite) · [IndirectRAG-Bench](https://huggingface.co/datasets/heisenberg-88/indirectrag-bench).

## Воспроизведение в рабочей копии

Для нового прогона укажите чистую папку результатов или используйте копию проекта без созданных before/after JSON. Для преобразования parquet нужен pyarrow. Обе версии проверяются последовательно в одном Python-окружении проекта.

~~~powershell
python -m experiment.v26.panel prepare
python -m experiment.v26.lock
python -m experiment.v26.bench before primary
python -m experiment.v26.bench after diagnostic primary
python -m experiment.v26.bench after public
python -m experiment.v26.model_only
python -m experiment.v26.model_only --before
python -m experiment.v26.report
python tests/run_all.py
~~~
